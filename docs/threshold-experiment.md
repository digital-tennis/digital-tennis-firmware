# DT-HW-31-23-00 · 실험으로 선택한 모션 임계값

R01 / 2026-10-20. NU40-DK+별도 외장 IMU용 C 실험 프로필의 임계값을 가상 센서 자료에서 선택한다. NU54 센서 없는 버튼 프로필과 보드의 기존 빠른 peak 기본값은 유지한다. 실제 센서/사람의 정확도나 전체 무선 지연 검증은 아니다.

## 패턴과 수치의 역할

횡회전의 부호로 포핸드/백핸드, overhead와 경기 상태로 서브/스매시, 짧은 회전으로 발리 의도, 대각선 아래/위 성분으로 슬라이스/로브 의도를 구분한다. 이 좌표/동작 가설은 사람이 정의했고, 방향·범위·시간·일관성·가속도 하한은 조정 표본의 C 특징 범위를 여유 있게 확장해 정한다. 새 학습 모델이나 모든 실제 테니스 동작을 발견한 결과가 아니다. 실제 발리의 바운드 전 여부·공의 스핀/적중은 게임 규칙의 책임이다.

## 실험을 고정하는 방법

`simulator/threshold-plan.json`을 먼저 기록한다. train 시드42017과 selection 시드42029를 각각 동작별24개로 만들고, holdout 시드52973은 값을 고정하기 전 생성하지 않는다. 예전 시드731091은 이미 확인한 자료이므로 새 최종 평가로 재사용하지 않는다.

속도0.7..1.3배·범위0.8..1.2배·잡음0.3..1.6배·offset0.20..0.30m·발리/슬라이스/로브 양쪽 타격·좌우손·Z축 장착0/90/180/270도를 섞는다. 이름/정답은 평가에서만 사용한다. C에는 7열 센서값과 장착/손/명시 경기 상태만 전달한다.

부정 표본은 정지·걷기·병진 흔들림·손 떨림·라켓 돌리기에 손잡이 축 회전·작은 자세 조정·느린 준비 자세·회전 방향이 바뀌는 손목 원운동을 더한9종이다. 이것이 모든 실생활 부정 동작을 대표하지는 않는다. 테니스와 완전히 동일한 우발적 움직임은 센서만으로 구분할 수 없어 별도 반례로 유지한다.

## 탐색 기준

시작140/160/180/200/220deg/s × 해제60/80deg/s × filter alpha0.25/0.4 =20개 검출기를 실제 C 코드로 실행한다. 각 검출기의 train 특징에서7종 범위를 추출하고, 선언한 여유 폭1/1.5/2배로 확장해 총60개 후보를 비교한다. 서브/스매시는 하나의 overhead 범위를 공유한다.

범위는 signed X/Z 적분을 회전 경로 길이로 나눈 방향, 회전 범위deg, 지속ms, 방향 일관성, 중력 포함 최고g를 사용한다. 준비 동작과 느린 복귀를 정답 스트로크 창으로 취급하지 않는다. 값의 유효성은 CSV 생성기와 `dt_controller_init`이 검사한다.

선택 우선순위는 다음과 같다.

1. 조정/선택 표본에서 부정 동작 오검출·다른 종류 출력·중복·잘못된 시점이 모두0인 후보만 허용한다.
2. 선택 표본의 macro recall, 가장 낮은 종류의 recall이 높은 후보를 고른다.
3. 동률이면 최대 판정 지연이 짧고, 시작 임계값이 높고, 범위 여유 폭이 작은 후보를 고른다.
4. 선택 CSV의 해시를 고정한 뒤 새 C 바이너리를 빌드한다. Python 선택용 범위 비교와 실제 C 출력이 train/selection 전체에서 일치해야 최종 평가를 연다.
5. 최종 합격 목표는 macro recall≥95%, 모든 종류 recall≥90%, 부정 오검출/중복/잘못된 시점/다른 종류 출력0이다. 실패하면 실패를 보고하고 같은 holdout에 맞춰 재조정하지 않는다.

전체는 같은 새 최종 표본에서 **663/700(94.7%) → 693/700(99.0%)**다. 발리는69→98개, 백핸드는99→95개로 줄었다. macro recall99%·최저 종류 recall95%가 사전에 정한95%/90% 기준을 통과했지만 모든 종류가 개선된 결과는 아니다. 백핸드5개는 학습된 시간 상한430ms·가속도 하한1.764g 밖이었고, 약한 발리2개는 적합한 검출 창이 생기지 않았다. 이7개와 전체 혼동 행렬을 보관하고 같은 holdout에 맞춰 값을 다시 조정하지 않았다.

일상 동작900개 오검출0, 중복0, 잘못된 시점0, 다른 종류로 오분류0이다. 피크 후 지연은 중앙값170→150ms, 최대380→360ms다. CPU 실행 시간·무선·Unity 전체 지연은 아니다. 합성 표본의 인식률을 실제 사용자 정확도로 해석하지 않는다.

[구조화 검증 기록](threshold-study-validation.json)은 계획/소스/CSV/ELF 해시와 누락 사례를, [전체60개 후보 표](threshold-candidates.csv)는 후보별 조정/선택 성능을 제공한다. 호스트7개·ASan/UBSan7개 검사군, 물리/연동9개·임계값/양쪽 타격6개 검사와4종 보드 구성 컴파일을 통과했다. 이전 실험 보고서는 그 커밋의 역사적 기록으로 유지한다.

## 코드와 재현 순서

```sh
cmake -S . -B .work/motion-simulator
cmake --build .work/motion-simulator
# 실험 출력 폴더는 새로 만들고 baseline 바이너리를 별도 보존한다.
python3 simulator/threshold_study.py tune --out .work/new-threshold-study
# 선택한 두 CSV를 검토해 적용한다.
cp .work/new-threshold-study/selected-rules.csv config/gesture-rules.csv
cp .work/new-threshold-study/selected-detector.csv config/gesture-detector.csv
cmake --build .work/motion-simulator
python3 simulator/threshold_study.py evaluate --out .work/new-threshold-study --baseline /absolute/path/baseline-replay
ctest --test-dir .work/motion-simulator --output-on-failure
```

`--baseline`은 선택 사항이다. 이전 실행 파일이 없으면 생략하고 새 C 경로만 평가한다. 이전 바이너리 결과와 새 바이너리를 비교할 때는 반드시 같은 holdout CSV를 사용한다. 생성 데이터를 재활용할 때는 소스/계획·CSV 해시를 확인한다. 방향 이름·기대 kind가 분류기에 전달되는 기능은 없다.

`config/gesture-detector.csv`는 실험 profile의 filter/start/release/cooldown/시간 gate, `config/gesture-rules.csv`는7종 범위다. CMake가 검증된 헤더를 만들고 `dt_motion_gesture_defaults()`와 `dt_gesture_classify_ring()`이 사용한다. 코드의 숫자를 다시 바꿀 필요 없이 CSV를 수정해 재빌드한다. 보드에서 런타임 CSV를 수신/로드하는 기능은 아니다. 호스트 `imu_replay`의 detector override는 실험용이며 무선 제어 명령이 아니다.

새 프로필의 경기 상태 C setter에 대응하는 BLE 명령은 아직 없고, 기본 `main.c`는 기존 빠른 peak 프로필을 유지한다. 실물 적용 전 NU40 센서 로그로 별도 사용자/세션 평가·전체 지연 예산·상태 전달을 검증한다. DT 문서 번호는 ATA iSpec 2200을 참고한 자체 관리 방식이며 공식 적합성을 주장하지 않는다. 자체 구현은 Apache-2.0이다.
